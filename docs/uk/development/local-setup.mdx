# Налаштування локальної розробки

Посібник з налаштування Ring Platform для локальної розробки.

<Audience for="founder">

## Що вам знадобиться

- Node.js 22, pnpm/npm та Git встановлені на вашому комп'ютері
- PostgreSQL 16 + PostGIS (через Homebrew, Docker або нативне встановлення)
- Редактор коду (рекомендується VS Code)

## Огляд налаштування

1. Клонуйте репозиторій
2. Встановіть залежності
3. Налаштуйте змінні середовища з `env.local.template`
4. Налаштуйте PostgreSQL та виконайте міграції
5. Запустіть сервер розробки

</Audience>

<Audience for="developer">

## Передумови

### Необхідне програмне забезпечення

- **Node.js 22** — [Завантажити з nodejs.org](https://nodejs.org/)
- **npm 10+** або **pnpm 9+** — Менеджер пакетів
- **Git** — Контроль версій
- **PostgreSQL 16** з розширенням **PostGIS** — Дивіться розділ налаштування бази даних
- **VS Code** — Рекомендоване IDE

### Додаткові інструменти

- **Docker** — Для контейнеризованого PostgreSQL (альтернатива встановленню через Homebrew)
- **Postman** або **Bruno** — Тестування API

## Встановлення

### 1. Клонування репозиторію

<Code language="bash" title="terminal">
{`git clone https://github.com/connectplatform/ring.git
cd ring`}
</Code>

### 2. Встановлення залежностей

<Tabs items={['npm', 'pnpm']}>
  <Tab value="npm">
    <Code language="bash" title="terminal">
{`npm install`}
</Code>
  </Tab>
  <Tab value="pnpm">
    <Code language="bash" title="terminal">
{`pnpm install`}
</Code>
  </Tab>
</Tabs>

### 3. Конфігурація середовища

Скопіюйте шаблон середовища:

<Code language="bash" title="terminal">
{`cp env.local.template .env.local`}
</Code>

<Callout type="warning">
Змінна `DB_BACKEND_MODE` є **обов'язковою** — платформа не запуститься без неї. Для локальної розробки з PostgreSQL встановіть `k8s-postgres-fcm`.
</Callout>

Налаштуйте ваш файл `.env.local` з такими обов'язковими змінними:

<Code language="bash" title="terminal">
{`# Режим бекенду бази даних (ОБОВ'ЯЗКОВО)
DB_BACKEND_MODE=k8s-postgres-fcm

# Підключення PostgreSQL
DB_HOST=localhost
DB_PORT=5432
DB_NAME=ring_platform
DB_USER=ring_user
DB_PASSWORD=ring_password_2024
DATABASE_URL=postgresql://ring_user:ring_password_2024@localhost:5432/ring_platform

# Auth.js v5
AUTH_SECRET=generate-a-random-secret-here
AUTH_TRUST_HOST=true
AUTH_GOOGLE_ID=your_google_client_id
AUTH_GOOGLE_SECRET=your_google_client_secret

# Застосунок
NEXT_PUBLIC_BASE_URL=http://localhost:3000
NODE_ENV=development`}
</Code>

<Callout type="tip">
Згенеруйте `AUTH_SECRET` за допомогою: `npx @better-auth/cli secret`
</Callout>

Повний перелік підтримуваних змінних та їх опис дивіться в [Конфігурація середовища](/docs/en/deployment/environment.mdx).

### 4. Налаштування бази даних

#### Варіант A: Docker (рекомендовано для локальної розробки)

<Code language="bash" title="terminal">
{`# Запуск PostgreSQL 16 з PostGIS
docker run -d \\
  --name ring-postgres-dev \\
  -e POSTGRES_USER=ring_user \\
  -e POSTGRES_PASSWORD=ring_password_2024 \\
  -e POSTGRES_DB=ring_platform \\
  -p 5432:5432 \\
  postgis/postgis:16-3.4`}
</Code>

#### Варіант B: Homebrew (macOS)

<Code language="bash" title="terminal">
{`brew install postgresql@16 postgis
brew services start postgresql@16

# Створення користувача бази даних та бази даних
createuser ring_user -P   # пароль: ring_password_2024
createdb ring_platform -O ring_user`}
</Code>

<Callout type="info">
Для локальної розробки з декількома клонами використовуйте скрипт ініціалізації `infrastructure/postgres/bootstrap-brew-dev.sh`. Дивіться `infrastructure/postgres/MIGRATION-KINGDOM-MATRIX.md`.
</Callout>

#### Виконання міграцій

<Code language="bash" title="terminal">
{`npm run db:migrate`}
</Code>

<Callout type="tip">
Файли міграцій знаходяться в директорії `data/`. Виконавець міграцій читає `DB_BACKEND_MODE` для вибору правильного адаптера. Для локального PostgreSQL (`k8s-postgres-fcm`) він застосовує SQL міграції з `data/schema.sql` та `data/migrations/`.
</Callout>

### 5. Запуск сервера розробки

<Code language="bash" title="terminal">
{`npm run dev`}
</Code>

Застосунок буде доступний за адресами:

- **Фронтенд**: http://localhost:3000
- **API маршрути**: http://localhost:3000/api/*
- **Перевірка стану**: http://localhost:3000/api/health

## Поширені проблеми

### Порт 3000 вже використовується

<Code language="bash" title="terminal">
{`npm run dev -- -p 3001`}
</Code>

### Відмовлено у з'єднанні з базою даних

1. Переконайтеся, що PostgreSQL працює: `pg_isready`
2. Перевірте значення `.env.local` для `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`
3. Переконайтеся, що база даних `ring_platform` існує
4. Підтвердьте, що `DB_BACKEND_MODE` встановлено на `k8s-postgres-fcm`

### Помилки OAuth Auth.js

1. Переконайтеся, що `AUTH_GOOGLE_ID` та `AUTH_GOOGLE_SECRET` вказано в `.env.local`
2. Перевірте, що `http://localhost:3000` є в дозволених URI перенаправлення консолі Google OAuth
3. Переконайтеся, що `AUTH_SECRET` встановлено та є однаковим
4. Формат URL зворотного виклику: `http://localhost:3000/api/auth/callback/google`

### Firebase FCM не працює (необов'язково)

Firebase використовується лише для push-сповіщень (FCM) у режимі `k8s-postgres-fcm`. Застосунок працюватиме без налаштованого Firebase, але push-сповіщення не будуть доставлятися. Налаштуйте змінні `AUTH_FIREBASE_*` та `NEXT_PUBLIC_FIREBASE_*` за потреби.
