# Початок роботи

Запустіть **white-label клон Ring Platform** на своєму комп’ютері. Цей хаб відображає реальний dev-flow з open-source дерева ([connectplatform/ring](https://github.com/connectplatform/ring)) і **ring-platform.org** — community-порталу для self-hosted ентузіастів.

<Callout type="info" title="Реалістичний час">
| Шлях | Час | Результат |
|------|-----|-----------|
| **`./install.sh --quick`** + наявний PostgreSQL | ~20–40 хв | Клон, залежності, env — схему та OAuth ще потрібно додати |
| **Повний Postgres-primary bootstrap** | 45–90 хв | Локальний стек як у production (`k8s-postgres-fcm`) |
| **Прототип (`firebase-full`)** | ~15–30 хв | Лише Firestore — без глибини ERP, News Kingdom, PaymentConductor |

Спочатку бачення? [Ласкаво просимо до Ring](/docs/welcome), потім поверніться сюди.
</Callout>

<Callout type="warning" title="OSS self-host vs Ringdom-managed">
**Self-host з GitHub?** Ця секція для вас. **Turn-key хостинг Ringdom?** Почніть на [ringdom.org](https://ringdom.org) — після handoff див. [Посібник з кастомізації](/docs/customization/customization-guide). Публічне OSS-дерево містить `install.sh`; enterprise k8s/CLI залишається поза публічною межею ([`FEATURESET.md`](https://github.com/connectplatform/ring/blob/main/FEATURESET.md)).
</Callout>

## Що ви налаштуєте

| Шар | Артефакт | Призначення |
|-----|----------|-------------|
| **Ідентичність клону** | `ring-config.json` | Брендинг, feature flags, домени (`ring-config.template.json`) |
| **Секрети та backend** | `.env.local` | `DB_BACKEND_MODE`, `AUTH_*`, Firebase FCM, tunnel deploy target |
| **Дані застосунку** | PostgreSQL `ring_platform` | `data/schema.sql` v4.0.1+ + kingdom migrations |
| **Auth** | Auth.js v5 (`auth.ts`) | `AUTH_SECRET` + щонайменше один OAuth-провайдер |
| **Dev runtime** | `server.ts` | `npm run dev` — Next.js 16 + React 19 + native WSS при `RING_DEPLOY_TARGET=self-hosted` |

## Рекомендований bootstrap (Postgres-primary)

<Callout type="success" title="Типово для ring-platform.org">
Production і локальний dev використовують **`DB_BACKEND_MODE=k8s-postgres-fcm`** — PostgreSQL для даних, Firebase Admin **лише для FCM push**, якщо налаштовано.
</Callout>

<Steps>

<Step>

### 1 — Клон і `install.sh`

<Code language="bash" title="terminal">
{`git clone https://github.com/connectplatform/ring.git
cd ring
chmod +x install.sh
./install.sh --quick`}
</Code>

`install.sh` v2.0 (див. [`INSTALL.md`](https://github.com/connectplatform/ring/blob/main/INSTALL.md)):

- Перевірка системних вимог (Node.js 20+, npm 10+)
- Створює **`ring-config.json`** з шаблону (`--clone-name` для white-label slug)
- Копіює **`env.local.template`** → **`.env.local`** з `AUTH_SECRET` і `WALLET_ENCRYPTION_KEY`
- Запускає **`npm install`**
- За потреби матеріалізує `next.config.mjs`, `docker-compose.yml`, `Dockerfile`

Прапорці: `--quick`, `--clone-name my-ring`, `--verbose`, `--help`.

</Step>

<Step>

### 2 — PostgreSQL

Запустіть Postgres 16+ і БД **`ring_platform`** (користувач **`ring_user`**). Варіанти:

- **Docker** — dev-контейнер (див. [Встановлення](/docs/getting-started/installation#postgresql-setup))
- **Ringdom monorepo** — `docker compose -f docker-compose.dev.yml up -d postgres` або `./infrastructure/postgres/bootstrap-brew-dev.sh`
- **Існуючий сервер** — створіть БД і вкажіть `DB_HOST` / `DB_*` у `.env.local`

</Step>

<Step>

### 3 — Схема та kingdom migrations

<Code language="bash" title="terminal">
{`export DATABASE_URL="postgresql://ring_user:ring_password_2024@localhost:5432/ring_platform"
psql "$DATABASE_URL" -f data/schema.sql
psql "$DATABASE_URL" -f data/migrations/002_news_content_schema.sql
psql "$DATABASE_URL" -f data/migrations/003_news_kingdom_upgrade.sql
psql "$DATABASE_URL" -f data/migrations/004_payment_transactions.sql`}
</Code>

Повний порядок і матриця клонів: [Міграції БД](/docs/getting-started/migrations). Хелпер: `./scripts/run-migration.sh` для контейнера `ring-postgres-dev`.

</Step>

<Step>

### 4 — Auth і локальні URL

Мінімум у `.env.local`:

<Code language="bash" title=".env.local">
{`DB_BACKEND_MODE=k8s-postgres-fcm
AUTH_SECRET=          # openssl rand -base64 32
AUTH_GOOGLE_ID=
AUTH_GOOGLE_SECRET=
NEXT_PUBLIC_BASE_URL=http://localhost:3000
RING_DEPLOY_TARGET=self-hosted
NEXT_PUBLIC_RING_DEPLOY_TARGET=self-hosted`}
</Code>

Додайте Google OAuth redirect: `http://localhost:3000/api/auth/callback/google`.

Інтерактивний майстер: `npm run setup:env` або `./scripts/setup-dev.sh`.

</Step>

<Step>

### 5 — Dev-сервер і валідація

<Code language="bash" title="terminal">
{`npm run dev`}
</Code>

Очікуйте: `Ready on http://localhost:3000 [self-hosted]` і native WSS на `/api/tunnel/ws`.

Далі [Перший успіх](/docs/getting-started/first-success) — homepage, `/login`, entities/opportunities без помилок адаптера БД. Опційно: `npm run type-check`, `npm run portal:health`.

<Callout type="success" title="Bootstrap завершено">
Відкрийте [http://localhost:3000](http://localhost:3000). Брендинг у `ring-config.json`, далі [Наступні кроки](/docs/getting-started/next-steps).
</Callout>

</Step>

</Steps>

## Альтернативні шляхи

<Tabs items={['Ручне налаштування', 'firebase-full прототип', 'Ringdom monorepo dev']}>

<Tab value="Ручне налаштування">

Без інсталятора — той самий результат, більше контролю:

<Code language="bash" title="terminal">
{`git clone https://github.com/connectplatform/ring.git
cd ring
npm install
cp env.local.template .env.local
cp ring-config.template.json ring-config.json
# edit ring-config.json + .env.local
# provision PostgreSQL + apply migrations (кроки 2–3 вище)
npm run dev`}
</Code>

Детально: [Встановлення](/docs/getting-started/installation).

</Tab>

<Tab value="firebase-full прототип">

Швидкий Vercel-edge прототип — **не** production data plane ring-platform.org:

<Code language="bash" title=".env.local">
{`DB_BACKEND_MODE=firebase-full`}
</Code>

Firebase Admin + client keys з `env.local.template`. Без `data/schema.sql`. Прогалини: [Вибір БД](/docs/customization/database-selection).

</Tab>

<Tab value="Ringdom monorepo dev">

Коли `ring-platform.org` у checkout Ringdom:

<Code language="bash" title="ringdom repo root">
{`docker compose -f docker-compose.dev.yml up -d postgres
cd ring-platform.org
npm install
# .env.local already or: npm run setup:env
npm run dev`}
</Code>

Маніфест multi-clone Postgres: `infrastructure/postgres/DEV-DATABASE-MANIFEST.json`.

</Tab>

</Tabs>

## Швидка довідка — bootstrap

| Завдання | Команда |
|----------|---------|
| One-command install | `git clone … && ./install.sh --quick` |
| Env wizard | `npm run setup:env` |
| Dev env script | `./scripts/setup-dev.sh` |
| Apply migration | `./scripts/run-migration.sh data/schema.sql` |
| Dev server | `npm run dev` |
| Type check | `npm run type-check` |
| Portal health | `npm run portal:health` |
| Repo install guide | [`INSTALL.md`](https://github.com/connectplatform/ring/blob/main/INSTALL.md) |

<Callout type="tip" title="install.sh vs setup-dev.sh">
**`install.sh`** — перший bootstrap клону (config + `npm install`). **`setup-dev.sh`** — після клону, hardening env. **`npm run setup:env`** — інтерактивний прохід по існуючому `.env.local`.
</Callout>
