# Wallet API

<Callout type="info">
  Filter with **Founder** / **Developer** in the docs sidebar. Server actions (preferred) and legacy REST routes. Oracle rate persisted in `platform_settings` / `web3` via `ring-token-oracle.ts` and `db()` — not a private Pool.
</Callout>

Ring Platform wallet operations are available through two layers:

1. **Server Actions** (preferred) — `app/_actions/wallet.ts` — 23 type-safe actions for direct call from React 19 components via `useActionState`.
2. **API Routes** (legacy) — `app/api/wallet/**/route.ts` — HTTP handlers preserved for external integration and MCP tools.

Browser calls use **Auth.js session cookies** on the same origin — see [API reference](/docs/api). UI entry: `/wallet` (protected).

### Server actions vs API routes

**Server actions** are the preferred integration pattern for React 19 components. They offer type safety, automatic cache invalidation (`revalidatePath`), and progressive enhancement (forms work without JavaScript). The **API routes** are preserved for webhook consumers, MCP tools, and non-React integrations.

### Typical member flows

- **First login** — `ensureUserWallets` action provisions custodial address (Solana or EVM per clone config) — atomic single-write, max one wallet per chain.
- **Check balance** — wallet page calls `listUserWallets` + `getWalletBalance`.
- **Set a wallet PIN** — calls `createPinAccessTokenAction` to validate PIN; activates PIN-wrapped encryption.
- **Send tokens** — `transferNativeTokens` with toAddress + amount; gas sponsored by treasury.
- **Top up credits** — `topUpCredits` with optional chain verification.
- **Pay in store** — `spendCredits` with order metadata.

<Callout type="warning">
  **Custodial model:** Ring signs transfers server-side for social-auth wallets. External wallets (MetaMask via RainbowKit) connect client-side — they do not use these custodial server actions.
</Callout>

</Audience>

## Server actions (preferred)

All 23 server actions are in `app/_actions/wallet.ts`. They follow the SSOT pattern: dynamic import of service → auth check → operation → cache invalidation.

### PIN access token action

<Code language="typescript" title="createPinAccessTokenAction">{`// app/_actions/wallet.ts
export interface PinAccessTokenState {
  success: boolean
  accessToken?: string      // Raw token — one-time, never persisted
  walletAddress?: string
  expiresAt?: string        // ISO timestamp, default 15-min TTL
  scope?: 'withdrawal' | 'transfer' | 'admin'
  error?: string
  requiresMigration?: boolean  // True when wallet needs v2 PIN re-encrypt
}

// Client usage:
const [tokenState, pinAction, isPending] = useActionState(
  createPinAccessTokenAction, null
)`}</Code>

### Integration with React 19

Server actions are called directly from client components using `useActionState`:

<Code language="typescript" title="useActionState pattern">{`import { useActionState } from 'react'
import { topUpCredits } from '@/app/_actions/wallet'

const [state, formAction, isPending] = useActionState(
  async (prevState, formData) => {
    const result = await topUpCredits(formData)
    if (result.success) await refreshCreditBalance()
    return result
  },
  null
)`}</Code>

Or with form progressive enhancement:

<Code language="tsx">{`<form action={formAction}>
  <Input name="amount" type="number" min="0.01" step="0.01" required />
  <Input name="txHash" placeholder="Transaction hash (optional)" />
  <Textarea name="description" />
  <Button type="submit" disabled={isPending}>
    {isPending ? 'Processing...' : 'Top Up'}
  </Button>
</form>`}</Code>

## Auth pattern

<Mermaid title="Server action handler">
{`sequenceDiagram
  participant C as Client (useActionState)
  participant A as Server Action
  participant S as auth()
  participant V as Service (dynamic import)

  C->>A: formAction(formData)
  A->>S: session
  alt not signed in
    A-->>C: { success: false, error: "Authentication required" }
  else authorized
    A->>V: dynamic import + call
    V-->>A: result
    A->>A: revalidatePath('/[locale]/wallet')
    A-->>C: { success: true, ... }
  end`}
</Mermaid>

## API routes (legacy — for external consumers)

The REST API routes are preserved for backward compatibility. New integrations should use server actions.

### Wallet lifecycle

| Method | Path | Notes |
|--------|------|-------|
| GET | `/api/wallet/list` | `{ wallets: Wallet[] }` from `listWallets()` |
| POST | `/api/wallet/ensure` | Idempotent create-if-missing; returns `address`, `chain` |
| GET | `/api/wallet/balance` | Default wallet native-token balance by chain |

**Deprecated routes:**
- `POST /api/wallet/create` — returns 410 Gone; wallets created via `ensureUserWallets` server action, not direct POST.
- `POST /api/wallet/pin-access` — returns 410 Gone; replaced by `createPinAccessTokenAction` server action (uses `wallet_access_tokens` table, sha256-hashed, 15-min TTL, single-use).

### Native-token on-chain operations

| Method | Path | Notes |
|--------|------|-------|
| GET | `/api/wallet/token/balance` | `{ balance, address, chain, symbol }` |
| POST | `/api/wallet/token/transfer` | Zod-validated; writes `wallet_transactions` row |
| POST | `/api/wallet/transfer` | **Deprecated** — legacy EVM POL/MATIC transfer (viem + Polygon); use `/api/wallet/token/transfer` for native-token path |

### Activity feed

| Method | Path | Query | Notes |
|--------|------|-------|-------|
| GET | `/api/wallet/activity` | `filter=all\|credit\|chain`, `limit`, `walletAddress?` | Unified feed via `getWalletActivityFeed()` |

**Deprecated:** `GET /api/wallet/history` — returns 410 Gone; use `/api/wallet/activity`.

### Credit ledger

| Method | Path | Notes |
|--------|------|-------|
| GET | `/api/wallet/credit/balance` | Balance, subscription stub, spend limits |
| PUT | `/api/wallet/credit/balance` | `{ user_id, amount, reason }` — admin airdrop |
| POST | `/api/wallet/credit/topup` | `CreditTopUpRequestSchema`; optional `tx_hash` verification |
| POST | `/api/wallet/credit/spend` | Debit for purchases; enforces min/max per tx |
| GET | `/api/wallet/credit/history` | `limit`, `after_id`, `type`, date filters |

SSOT schemas: `lib/zod/credit-schemas.ts`. Service: `features/wallet/services/credit-balance-service.ts`.

### Solana desk (quote / execute)

| Method | Path | Notes |
|--------|------|-------|
| GET | `/api/wallet/desk/quote` | Query `side`, `amount` → desk quote token |
| POST | `/api/wallet/desk/execute` | `{ idempotencyKey, quoteToken }` → on-chain desk swap |

### Environment variables

| Variable | Required | Used by |
|----------|----------|---------|
| `WALLET_ENCRYPTION_KEY` | Yes | `encrypt-wallet-secret.ts` — AES-256-GCM encryption of private keys |
| `SOLANA_RPC_URL` | Yes | `solana-client.ts` — on-chain Solana operations |
| `SOLANA_TREASURY_PRIVATE_KEY` | Yes | `treasury-transfer-service.ts` — sponsored gas transfers |
| `WALLET_ACCESS_TOKEN_TTL_SECONDS` | No (default: 900) | `pin-access-token-db.ts` — single-use token TTL |
| `POLYGON_RPC_URL` | For EVM chains | `get-wallet-balance.ts` — EVM balance fallback path |
| `ORACLE_QUOTE_SECRET` | For desk | Desk quote HMAC — falls back to `WALLET_ENCRYPTION_KEY` |
| `RING_ORACLE_DEFAULT_RATE` | No | Oracle fallback when DB disabled or row missing |
| `PLATFORM_SETTINGS_DISABLE_DB` | No | `true` → env-only oracle reads; writes throw |

### Oracle persistence

<Mermaid title="Oracle read/write path">
{`sequenceDiagram
  participant A as Server action / API
  participant O as ring-token-oracle.ts
  participant D as db() DatabaseService
  participant P as platform_settings/web3

  A->>O: getRingPerUsdRate()
  alt PLATFORM_SETTINGS_DISABLE_DB=true
    O-->>A: RING_ORACLE_DEFAULT_RATE
  else DB enabled
    O->>D: readDoc(platform_settings, web3)
    D->>P: JSONB oracle.ringPerUsd
    P-->>A: rate string
  end`}
</Mermaid>

Admin write path: `setRingPerUsdRate` or `POST /api/admin/web3/settings` → `setRingPerUsdRate()` in oracle service → `db().updateDoc` / `createDoc`.
