# Wallet API

<Callout type="info">
  Filter with **Founder** / **Developer** in the docs sidebar. Legacy copy claimed **10 endpoints**, HSM multi-sig, DEX swaps, NFT APIs, KYC/AML engines, and `Authorization: Bearer` JWT — **none verified**. Below matches `app/api/wallet/**/route.ts` as of v1.6.0.
</Callout>

Ring wallet HTTP handlers cover three layers:

1. **Custodial chain wallets** — auto-created for signed-in members; private keys encrypted with `WALLET_ENCRYPTION_KEY`.
2. **On-chain RING** — balance + send via native chain from `ring-config.json` (`chains.native`, default **Solana**; EVM Polygon path also wired).
3. **In-app credit ledger** — Postgres/Firestore-backed RING credits for store, subscriptions, and top-ups (distinct from on-chain balance).

Browser calls use **Auth.js session cookies** on the same origin — see [API reference](/docs/api). UI entry: `/wallet` (protected).

### Typical member flows

- **First login** — app calls `POST /api/wallet/ensure` → custodial address returned (Solana or EVM per clone config).
- **Check RING** — wallet page → `GET /api/wallet/ring/balance`.
- **Send RING to a contact** — `POST /api/wallet/ring/transfer` with `toAddress`, `amount`, optional `ringContactId`.
- **Top up credits** — `POST /api/wallet/credit/topup` (optional on-chain `tx_hash` proof when chain verification is enabled).
- **Pay in store** — `POST /api/wallet/credit/spend` with order metadata.

<Callout type="warning">
  **Custodial model:** Ring signs transfers server-side for social-auth wallets. External wallets (MetaMask via RainbowKit) connect client-side — they do not use these custodial POST routes.
</Callout>

## Auth pattern

<Mermaid title="Wallet route handler">
{`sequenceDiagram
  participant C as Client (cookie)
  participant R as /api/wallet/*
  participant A as auth()
  participant S as Wallet service

  C->>R: fetch credentials include
  R->>A: session
  alt not signed in
    R-->>C: 401
  else authorized
    R->>S: Zod / service call
    S-->>R: balance | txHash | ledger row
    R-->>C: JSON`}
</Mermaid>

<Code language="bash" title="Same-origin session">{`curl -s "http://localhost:3000/api/wallet/ring/balance" \\
  -H "Cookie: authjs.session-token=YOUR_SESSION_COOKIE" | jq .`}</Code>

**Required env (custodial signing):** `WALLET_ENCRYPTION_KEY` (32-byte hex). **Chain:** `NEXT_PUBLIC_RING_TOKEN_ADDRESS`, `POLYGON_RPC_URL`, `SOLANA_RPC_URL` per [Environment](/docs/deployment/environment). Native chain: `getNativeChain()` from `lib/ring-config-chain.ts`.

## Route inventory (verified)

### Wallet lifecycle

| Method | Path | Auth | Notes |
|--------|------|------|-------|
| GET | `/api/wallet/list` | Session | `{ wallets: Wallet[] }` from `listWallets()` |
| POST | `/api/wallet/create` | Session | Body `{ label? }` → `{ wallet }`; visitors forbidden |
| POST | `/api/wallet/ensure` | Session | Idempotent create-if-missing; returns `address`, `chain`, `wallets[]` |
| GET | `/api/wallet/balance` | Session | Default wallet **native POL** balance on Polygon via viem |

**Not implemented:** `GET /api/wallet` root, mnemonic export, multi-sig config JSON.

### RING on-chain

| Method | Path | Body / query | Notes |
|--------|------|--------------|-------|
| GET | `/api/wallet/ring/balance` | — | `{ balance, address, chain, symbol: "RING" }` |
| POST | `/api/wallet/ring/transfer` | `{ toAddress, amount, contactUserId?, ringContactId?, notes? }` | Zod-validated; writes `wallet_transactions` row |

Native chain follows `ring-config.json` → `chains.native` (`solana` \| `evm`). Solana transfers may use fee sponsorship when configured.

### Legacy / deprecated

| Method | Path | Status |
|--------|------|--------|
| POST | `/api/wallet/transfer` | **Deprecated** — POL-only; logs warn to use `/api/wallet/ring/transfer` |
| GET | `/api/wallet/history` | **410 Gone** → use `/api/wallet/activity` |
| POST | `/api/wallet/pin-access` | **410 Gone** — PIN flow removed; server-side encryption only |

### Activity feed

| Method | Path | Query | Notes |
|--------|------|-------|-------|
| GET | `/api/wallet/activity` | `filter=all\|credit\|chain`, `limit`, `walletAddress?` | Unified feed via `getWalletActivityFeed()` |

### Credit ledger

| Method | Path | Auth | Notes |
|--------|------|------|-------|
| GET | `/api/wallet/credit/balance` | Session | Balance, subscription stub, spend limits (partially hard-coded) |
| PUT | `/api/wallet/credit/balance` | Platform admin | `{ user_id, amount, reason }` — admin airdrop |
| POST | `/api/wallet/credit/topup` | Session | `CreditTopUpRequestSchema`; optional `tx_hash` verification |
| POST | `/api/wallet/credit/spend` | Session | Debit for purchases; enforces min/max per tx |
| GET | `/api/wallet/credit/spend` | Session | `period=day\|week\|month\|year` spending summary |
| GET | `/api/wallet/credit/history` | Session | `limit`, `after_id`, `type`, date filters |

SSOT schemas: `lib/zod/credit-schemas.ts`. Service: `features/wallet/services/user-credit-service.ts`.

### Solana desk (quote / execute)

| Method | Path | Notes |
|--------|------|-------|
| GET | `/api/wallet/desk/quote` | Query `side`, `amount` → desk quote token |
| POST | `/api/wallet/desk/execute` | `{ idempotencyKey, quoteToken }` → on-chain desk swap |

Desk oracle + compliance limits: superadmin `GET/POST /api/admin/web3/settings` ([Admin API](/docs/api/admin)).

### Example — send RING

<Step>

### Ensure wallet exists

<Code language="bash" title="curl">{`curl -X POST "http://localhost:3000/api/wallet/ensure" \\
  -H "Cookie: authjs.session-token=..."`}</Code>

</Step>
<Step>

### Transfer

<Code language="bash" title="curl">{`curl -X POST "http://localhost:3000/api/wallet/ring/transfer" \\
  -H "Content-Type: application/json" \\
  -H "Cookie: authjs.session-token=..." \\
  -d '{"toAddress":"RECIPIENT","amount":"10.5"}'`}</Code>

</Step>
<Step>

### Confirm in activity feed

<Code language="bash" title="curl">{`curl -s "http://localhost:3000/api/wallet/activity?filter=chain&limit=10" \\
  -H "Cookie: authjs.session-token=..." | jq .`}</Code>

</Step>
</Steps>

### Client-side Web3 (not these routes)

External wallet connect uses **wagmi + viem + RainbowKit** (`contexts/web3-context.tsx`, `constants/web3.ts`). Token addresses come from env — not from `GET /api/wallet/tokens` (not implemented).
