# First Success Validation

<Callout type="info">
  Filter with **Founder** / **Developer** in the docs sidebar. Run this **after** [Installation](/docs/getting-started/installation) and [Migrations](/docs/getting-started/migrations). Estimated time: **10–15 minutes** for core checks; Web3 and payments are optional follow-ups.
</Callout>

**First success** means the dev server serves pages, **Auth.js** can establish a session, **DatabaseService** reads/writes without adapter errors, and core marketplace routes load. It does not require WayForPay, FCM, or wallet connectivity on day one.

## Success levels

| Level | Criteria | Good enough to… |
|-------|----------|-----------------|
| **Core** | Homepage + `/api/health` + sign-in + one CRUD path | Customize branding, invite testers |
| **Extended** | Tunnel test `ready`, entities + opportunities UI | Demo realtime notifications |
| **Optional** | Wallet balance, Web3 connect, payments sandbox | Token / checkout features |

## What founders should validate

Before showing the clone to stakeholders, confirm the **happy path** a member would take:

<Cards>
  <Card title="Land on the homepage" href="/docs/getting-started/installation">
    No blank screen or “database adapter” errors in the terminal.
  </Card>
  <Card title="Sign in" href="/docs/features/authentication">
    Google, Apple, or Resend magic link — whichever you configured in Google Cloud / Resend.
  </Card>
  <Card title="Create an entity" href="/docs/features/entities">
    Proves Postgres JSONB writes and your role gates work.
  </Card>
  <Card title="Browse opportunities" href="/docs/features/opportunities">
    Confirms list pages and discovery caches are wired.
  </Card>
</Cards>

<Callout type="tip" title="Partial success is OK">
  If auth and one CRUD flow work but push notifications or wallet are not configured yet, you still have a **valid dev clone**. Add FCM and PaymentConductor before production checkout ([Environment](/docs/deployment/environment)).
</Callout>

### When to stop and fix

- Terminal shows repeated Postgres connection failures → revisit [Prerequisites](/docs/getting-started/prerequisites) `DB_*` vars.
- Login redirects loop → `AUTH_SECRET` and OAuth redirect URIs (`http://localhost:3000/api/auth/callback/google`).
- Entity save fails with 403 → expected for **visitor** role; sign in as **member** or adjust test account role.

</Audience>

## Smoke-test procedure

<Steps>
<Step>

### 1 — Dev server

<Code language="bash" title="terminal">{`npm run dev`}</Code>

Expect Next.js ready on `http://localhost:3000`. Custom `server.ts` may log native WSS when `RING_DEPLOY_TARGET=self-hosted`.

</Step>
<Step>

### 2 — Health endpoint

<Code language="bash" title="curl">{`curl -sS http://localhost:3000/api/health | jq .
curl -I http://localhost:3000/api/health   # HEAD → 200 when alive`}</Code>

Real shape (`app/api/health/route.ts`): `status` is `healthy` | `degraded` | `unhealthy` (not `"ok"`). `services.database` is `postgresql` or `firebase`. Missing `AUTH_SECRET` → `degraded` and HTTP **503**.

</Step>
<Step>

### 3 — Homepage

<Code language="bash" title="terminal">{`curl -sS -o /dev/null -w "%{http_code}\n" http://localhost:3000/`}</Code>

Expect **200**. Open in browser; check console for red errors (ignore dev-only Auth.js JWT noise documented in `lib/logger.ts` filters).

</Step>
<Step>

### 4 — Authentication

1. Visit `/login` (locale prefix may apply: `/en/login`).
2. Complete **one** configured provider from `auth.ts`: Google OAuth, Apple, Resend magic link, Google One Tap, or crypto wallet — not GitHub/Discord (not in default provider list).
3. Confirm session: `/profile` shows user data; refresh persists session.

Optional: `GET /api/auth/session` with browser cookies returns `{ user: { id, email, role, … } }`.

</Step>
<Step>

### 5 — PostgreSQL (postgres-primary)

<Code language="bash" title="psql">{`psql "$DATABASE_URL" -c "SELECT COUNT(*) FROM users;"`}</Code>

Expect count ≥ 1 after first sign-in. No `/api/test-db` route in this tree — use `psql` or authenticated API calls.

</Step>
<Step>

### 6 — Authenticated APIs

`/api/entities` and `/api/opportunities` require a session — **401 without cookies is expected**.

After browser login, DevTools → copy session cookie, or test in UI:

1. `/entities` — list + create entity form submits.
2. `/opportunities` — list loads for your role.

</Step>
<Step>

### 7 — Tunnel readiness

<Code language="bash" title="curl">{`curl -sS http://localhost:3000/api/tunnel/test | jq .status, .availableProviders`}</Code>

Expect `"ready"` and provider list from `lib/tunnel/config`. For live SSE: Network tab → `/api/tunnel/sse` after sign-in. See [Tunnel protocol](/docs/features/tunnel-protocol).

</Step>
<Step>

### 8 — Optional checks

| Check | Command / action | Expected |
|-------|------------------|----------|
| TypeScript | `npm run type-check` | Exit 0 |
| Wallet API | `GET /api/wallet/balance` (logged in) | `{ balance }` or 404 until wallet created |
| Build | `npm run build` | Completes (runs type-check by default) |

</Step>
</Steps>
