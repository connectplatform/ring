# Generative Gallery

Generative Gallery is Ring Platform’s **shared media field** for NFT create and multi-vendor product forms. Operators and members **upload** images or **generate** four ImageConductor variations, enrich prompts with **Ghost-write** (TextConductor + web search), and keep history in a **hidden tool chat** (`genmedia:…`) that never clutters Messages.

<Callout type="info">
  Use **Founder** / **Developer** tabs in the docs sidebar to filter this page. Founders see operator value and surfaces; developers see modules, billing, and verified paths.
</Callout>

## Where it ships

| Surface | Role |
|---------|------|
| NFT create wizard | Collection cover + mint media via `GenerativeMediaField` (`scope: 'nft'`) |
| Vendor / admin product form | Product image gallery (`scope: 'product'`); admin reuses the same form |
| Product detail gallery | Prefers `derivatives.thumb` / `webpUrl` for strip; lightbox uses original |
| News cards / hero / OG | `pickImageSrc` → card / hero / og; blur LQIP when present |
| Avatar | `avatarThumb` (sync_thumb) preferred over `photoURL` original |
| Chat image bubbles | `MessageAttachment.derivatives.thumb` preferred over original URL |
| NFT mint + listings | Off-chain Metaplex JSON (`image`, optional `animation_url`, `properties.files`) + showcase on ownership / listing details |

SSOT module: `features/generative-media/`.

<Audience for="founder">

## Why this matters for your clone

- **One field, two businesses** — the same Upload \| Generate widget powers store catalog photos and member NFT art, so vendors and creators learn one workflow.
- **Credit-first spend** — Ghost-write and image generation debit platform credits through WalletConductor before the turn runs; insufficient balance fails early with a clear error.
- **Clean inbox** — generation history lives in a product-tool conversation marked hidden (`generative_gallery` / `genmedia:`), so Messages stays for real people.
- **Faster storefront paint** — with `storage.provider=ring_filebase`, uploads return a full `derivatives` map (`thumb`, `blur`, cards, …) under `{fileId}_v_*`; UI prefers thumbs for list/gallery first paint and originals in lightbox.
- **Richer NFT showcase** — mint builds Metaplex off-chain metadata with gallery files; listing details can show animation + gallery thumbs when present.

### Operator checklist

- Ensure ImageConductor / TextConductor providers are configured (same stack as other generative features).
- Fund or sell **platform credits** so Ghost-write and Generate can bill (`GENERATIVE_CREDIT_*` optional overrides; code defaults apply).
- Prefer **`ring_filebase`** so image ladders come from RingFileBase on upload (no Next-side sharp required for those paths). Optional `storage.webpDerivative.provider=sharp` remains a soft fallback for non-RingBase providers.
- Train vendors: Upload tab for photos; Generate tab for AI variations; set primary before save.
- On NFT listings, verify showcase thumbs/animation when creators attach multi-item galleries.

## Architecture

Credit-first generative turns run through server actions → `features/generative-media/service.ts` → ImageConductor / TextConductor, with optional WebP derive and FCM/in-app notify when generation completes in the background.

<Mermaid title="Generative gallery image turn">
{`sequenceDiagram
  participant UI as GenerativeMediaField / EditorFsModal
  participant SA as app/_actions/generative-media
  participant Bill as billing.billGenerativeTurn
  participant WC as WalletConductor.spendCredits
  participant Svc as generative-media/service
  participant IC as ImageConductor
  participant WebP as deriveWebpSibling
  participant Chat as hidden product conversation

  UI->>SA: runGenMediaImageAction
  SA->>Svc: runGenMediaImageTurn
  Svc->>Bill: action image_gen + referenceId
  Bill->>WC: spendCredits
  WC-->>Bill: transactionId
  Bill-->>Svc: ok
  Svc->>Chat: user prompt message
  Svc->>IC: generate n=4 + referenceImages
  IC-->>Svc: image URLs
  Svc->>WebP: per image
  Svc->>Chat: ImageConductor attachments
  opt notifyIfBackground
    Svc->>Svc: createNotification IN_APP + PUSH
  end
  Svc-->>UI: galleryItems
`}
</Mermaid>

### Billing (credit-first)

`billGenerativeTurn` prices from env (optional) with code defaults:

| Action | Env key | Default credits |
|--------|---------|-----------------|
| Ghost-write | `GENERATIVE_CREDIT_GHOST_WRITE` | `5` |
| Image gen | `GENERATIVE_CREDIT_IMAGE` | `15` |
| Video gen (priced; studio polish TBD) | `GENERATIVE_CREDIT_VIDEO` | `50` |

Flow: soft-idempotent on `referenceId` in `generative_usage` → `creditBalanceService.hasSufficientBalance` → `WalletConductor.spendCredits` → ledger row (warn-only if collection write fails).

<Callout type="tip">
  Optional `GENERATIVE_CREDIT_*` keys are listed in `env.local.template`. When `storage.provider` is **`ring_filebase`**, prefer the upload API’s `derivatives` map (`{fileId}_v_*` keys) over Next-side sharp. Optional `ring-config.storage.webpDerivative` remains for other providers (`provider: "off"` default; `"sharp"` imports sharp). Ops override: `IMAGE_WEBP_DISABLED=1`.
</Callout>

### Image turn details

- Prompt required, max **4000** characters.
- `ImageConductor.generate`: `n: 4`, `aspectRatio: '1:1'`, up to **3** `referenceImages`.
- Uploads post as `type: 'image'` with **empty caption** and `metadata.kind: 'gallery_upload'`.
- Ghost-write uses `TextConductor.generate` with `webSearch: true` and returns enriched prompt only.

### Conversation channel reuse

Generative Gallery does **not** introduce `Conversation.type: 'generative'`. It reuses the **`product` channel** (same as the store product agent) and annotates the subtype:

| Field | Value |
|-------|--------|
| `type` | `'product'` |
| `metadata.kind` | `'generative_gallery'` |
| `metadata.hiddenFromInbox` | `true` |
| `metadata.productId` / `subject` | `genmedia:{scope}:{entity}:{page}:{field}` from `buildGenMediaChatKey` |

Store product-agent chats also use `type: 'product'` with a real catalog `productId` and **no** tool `kind` — they remain **visible** in Messages. Taxonomy SSOT: [Real-Time Messaging](/docs/features/messaging).

`isHiddenToolConversation` returns true when metadata has `hiddenFromInbox`, `kind === 'generative_gallery'`, or `productId` / `subject` starts with `genmedia:` or `imggen:` (legacy). Prefer setting `hiddenFromInbox` on new tool chats.

Message payload kinds (`gallery_upload`, `ghost_write_request`, `image_gen_complete`, …) are **message** metadata — separate from conversation `metadata.kind`.
