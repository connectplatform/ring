# Authentication

<Callout type="info">
  Use **Founder** / **Developer** tabs in the docs sidebar to filter this page.
</Callout>

<Callout type="success" title="Executive summary">
Ring uses **Auth.js v5** for JWT sessions and OAuth. Members can sign in with **Ring Mailer** (OTP / magic link / password), **Google**, **Telegram** (web OIDC **or** Mini App `initData`), **Apple**, or a **crypto wallet**. Email is **not** Resend — see [Ring Mailer & RingdomX Mail](/docs/features/ring-mailer).
</Callout>

## Protection model

| Layer | Role |
|-------|------|
| `proxy.ts` | Locale rewrite + optimistic redirect to `ROUTES.LOGIN(locale)` (cookie presence only) |
| `proxy.ts` soft-gate | If JWT `needsOnboarding === true`, redirect to `/{locale}/login/onboarding` (exempt: `/login*`, `/auth*`, `/register*`, home `/`) |
| `(authenticated)/[locale]/layout.tsx` | `await auth()` — canonical session gate |
| `(admin)/[locale]/layout.tsx` | Role check (admin / superadmin) |
| `/login` | `LoginAuthenticatedRedirect` — client `useSession` bounce (skips during OAuth callback params) |
| `/register` | **Redirects to `/login`** (password signup demoted; OTP/magic is the product surface) |
| API routes | Per-handler `auth()` |

OAuth callbacks live under `/api/auth/*` (excluded from intl middleware). See [Proxy and intl](/docs/architecture/proxy-and-intl).

Login path SSOT: `ROUTES.LOGIN(locale)` with unified `from` / `callbackUrl` / `returnTo` (`features/auth/components/login-authenticated-redirect.tsx`).

### Vitals onboarding gate

After first sign-in, some providers require profile vitals (name, etc.) before the rest of the app. `isVitalsGatedProvider()` in `features/auth/lib/vitals-onboarding.ts` includes:

| Provider id | Gated? |
|-------------|--------|
| `google`, `google-one-tap`, `apple` | Yes |
| `email-otp`, `email-magic`, `telegram`, `crypto-wallet` | Yes |
| Others | Not in the shared gate set |

Incomplete vitals set JWT/session `needsOnboarding`. Client redirects (`email-login-form`, `verify-client`, wallet-connect) and the proxy soft-gate both honor it. Own profile Avatar uses `editable={true}` so members can finish photo vitals on `/profile`.

## Providers (shipped)

| Provider | How members sign in |
|----------|---------------------|
| **Ring Mailer** | OTP, magic link (`/verify#token=…`), or password — Credentials `email-otp` / `email-magic` / `credentials` |
| **Google** | OAuth redirect + Google One Tap (GIS JWT verified server-side) |
| **Telegram (web)** | OIDC Authorization Code + PKCE at `oauth.telegram.org` — `signIn('telegram')` |
| **Telegram Mini App** | Credentials `telegram-miniapp` — `signIn('telegram-miniapp', { initData, redirect: false })` |
| **Apple** | Sign in with Apple OAuth |
| **Crypto wallet** | Nonce + signature (`crypto-wallet` Credentials) |

GitHub/Discord OAuth are **not** in the default `auth.ts` provider list.

### Telegram surfaces (do not mix crypto)

| Surface | Purpose | Crypto / secret |
|---------|---------|-----------------|
| **Login via Telegram** (web) | Unauthenticated member opens a Ring session in the browser | OIDC `id_token` — `AUTH_TELEGRAM_ID` / `AUTH_TELEGRAM_SECRET` |
| **Mini App initData** | Silent session inside a Telegram WebApp client | HMAC with secret key `WebAppData` — bot API token (`TELEGRAM_MINI_APP_BOT_TOKEN` preferred) |
| **Link Telegram** (profile) | Already logged-in member binds Telegram id | Login Widget HMAC `SHA256(bot_token)` — `ADMIN_BOT_TOKEN` / `TELEGRAM_LOGIN_BOT_TOKEN` |
| **Admin bot** | Platform admins moderate from chat | Bot API + whitelist — [Manage via Telegram](/docs/features/manage-via-telegram) |
| **Stars membership** | Recurring / one-shot XTR invoice via SubscriptionConductor | Same Mini App bot token family — [SubscriptionConductor](/docs/features/subscriptions) |

Do **not** reuse Mini App `initData` (WebAppData) HMAC for Login Widget linking, and do **not** use Login Widget `SHA256(bot_token)` math for Mini App auth.

## What operators need

- **At least one** working sign-in path for testers (Google, Telegram, Apple, or Ring Mailer SMTP / Ethereal).
- For white-label production, prefer **domain-branded** auth mail via Ring Mailer or [RingdomX Mail](/docs/features/ring-mailer).
- Sessions are platform UUIDs (`users.id`); email can link accounts across providers when Auth.js linking is enabled. Telegram-only users may have an empty email (allowed by the partial unique index).

### Enable Telegram Login — web OIDC (BotFather checklist)

1. Open **@BotFather** → your bot → **Bot Settings → Web Login**.
2. Add **Allowed URLs**: site origin (e.g. `https://your.domain`) and OIDC callback `https://your.domain/api/auth/callback/telegram`.
3. Copy **Client ID** and **Client Secret** into cluster secrets / `.env.local` as `AUTH_TELEGRAM_ID` / `AUTH_TELEGRAM_SECRET`.
4. Keep the **bot API token** (`ADMIN_BOT_TOKEN` or `TELEGRAM_LOGIN_BOT_TOKEN`) for profile “Link Telegram” widget hash — it is **not** the OIDC client secret.
5. Confirm login page shows **Continue with Telegram** and a successful redirect lands on profile (or your `from` URL).

### Enable Telegram Mini App auth (operator view)

1. Create or reuse a bot that hosts the Mini App (can be the same bot as admin/login, or a dedicated one).
2. Set `TELEGRAM_MINI_APP_BOT_TOKEN` to that bot’s API token (preferred). Fallbacks used by `getTelegramMiniAppBotToken()`: `TELEGRAM_BOT_TOKEN` → `ADMIN_BOT_TOKEN` → `TELEGRAM_LOGIN_BOT_TOKEN` → `N9LIFE_BOT_TOKEN`.
3. Your Mini App client must call `signIn('telegram-miniapp', { initData, redirect: false })` with `Telegram.WebApp.initData` — platform ships the Credentials provider; a stock `/tg-mini-app` shell page is **not** on the main platform clone (white-labels may add their own).
4. Same resolver as OIDC: members get a platform UUID via `resolveOrCreateTelegramUser` (accounts + `communication.telegramId`).

<Callout type="tip" title="Privacy copy">
  Soft-launch OIDC scopes are `openid profile` — Ring reads Telegram **id**, **name**, **username**, and **photo**. Phone is not requested until you opt into the `phone` scope later. Mini App auth only uses fields present in verified `initData` (no phone by default).
</Callout>

<Callout type="warning" title="Resend removed">
  Do not create a Resend API key. `AUTH_RESEND_KEY` is deprecated. Configure Auth `SMTP_*` or `EMAIL_MODE=ethereal` instead. CRM inbox SMTP is a separate channel plane — see [Email AI-CRM](/docs/features/email-ai-crm).
</Callout>

<Callout type="tip" title="/register retired">
  Bookmarks to `/register` land on `/login` (locale + `from` / `callbackUrl` preserved). `EmailSignupForm` is removed from the auth barrel — use OTP / magic on the login form.
</Callout>

## Auth.js layout

| File | Role |
|------|------|
| `auth.config.ts` | Edge-safe config (minimal callbacks; **no** providers) |
| `auth.ts` | Full providers + adapter + JWT/session/`signIn` callbacks |
| `lib/auth/telegram-oidc.ts` | `TelegramOidcProvider`, claim map, lazy JWKS verify |
| `lib/auth/telegram-miniapp-initdata.ts` | WebAppData HMAC parse/verify + `getTelegramMiniAppBotToken` |
| `lib/auth/telegram-login-widget-hash.ts` | Legacy widget HMAC + `auth_date` window |
| `features/auth/services/user-resolve.ts` | `resolveOrCreateTelegramUser`, `syncUserTelegramCommunication`, `unlinkTelegramCommunication` |
| `features/auth/components/telegram-signin-button.tsx` | Same-tab `signIn('telegram')` |
| `lib/auth/session-user-status.ts` | `applyUserRowToJwt` — rehydrates `telegramId` from communication |
| `app/api/auth/[...nextauth]/route.ts` | Auth.js handlers (includes `/api/auth/callback/telegram`) |
| `app/api/auth/telegram/callback/route.ts` | **Linking only** — requires existing session |
| `app/api/telegram/stars-bot/webhook/route.ts` | Stars `pre_checkout_query` + `successful_payment` |

OIDC registers only when `AUTH_TELEGRAM_ID` and `AUTH_TELEGRAM_SECRET` are both set (`isTelegramOidcConfigured()`). Mini App Credentials `telegram-miniapp` is always registered; authorize fails closed if the bot token is missing or HMAC fails.

### Telegram OIDC flow (web)

1. UI: `TelegramSignInButton` → `signIn('telegram', { callbackUrl })` (same-tab redirect, matches Google GIS UX).
2. Auth.js: Authorization Code + PKCE + `state` against `https://oauth.telegram.org`.
3. Token exchange: Basic auth with Client ID/Secret; profile from **id_token** (no UserInfo endpoint).
4. `signIn` callback: `resolveOrCreateTelegramUser` — prefer `accounts` (`provider: telegram`), then `communication.telegramId`; optional verified-phone link when `phone` scope is used later.
5. Persist: `accounts` row + `users.data.communication.telegramId` (indexed); JWT/session may expose `telegramId`.
6. JWT refresh: `applyUserRowToJwt` rehydrates (or clears) `token.telegramId` from `communication.telegramId` on every session update — link/unlink without re-login.

### Telegram Login Widget (profile linking)

1. Env: `NEXT_PUBLIC_TELEGRAM_LOGIN_BOT_USERNAME` (no `@`) **must** match the bot whose token verifies the widget hash (`TELEGRAM_LOGIN_BOT_TOKEN` or `ADMIN_BOT_TOKEN`).
2. BotFather → Domain: host must match the site origin that embeds the widget.
3. UI: `TelegramLinkingModal` → official `telegram-widget.js` → `POST /api/auth/telegram/callback` (session required).
4. Callback calls `syncUserTelegramCommunication` — stores numeric **UID** (SSOT), optional `@username` for display, awards `addedTelegram` once on newly linked.
5. Unlink: profile **Unlink Telegram** → `unlinkTelegramAccount` → clears `communication.telegramId` + invalidates admin-bot whitelist cache; next `session.update()` clears JWT `telegramId`.

**UID SSOT:** `isTelegramLinked` requires a numeric `telegramId`. Username alone is never sufficient for rewards, whitelist, or “linked” UI.

### Telegram Mini App initData flow

1. Client (inside Telegram WebApp): read `window.Telegram.WebApp.initData`.
2. `signIn('telegram-miniapp', { initData, redirect: false })`.
3. `authorize` in `auth.ts`: `getTelegramMiniAppBotToken()` → `verifyTelegramMiniAppInitData` → `isTelegramMiniAppAuthDateFresh` (max age **86400s**).
4. HMAC algorithm (Telegram WebApps docs): `secret_key = HMAC_SHA256(key="WebAppData", message=bot_token)`; compare hex digest of sorted `key=value` lines (excluding `hash`).
5. Resolve user with `resolveOrCreateTelegramUser` (same path as OIDC).

Tests: `__tests__/auth/telegram-miniapp-initdata.test.ts` (WebAppData HMAC vectors). Widget crypto remains in `__tests__/auth/telegram-login-crypto.test.ts`.

### Ring Mailer (email)

Wire Auth `SMTP_*` or `EMAIL_MODE=ethereal`, apply `038_email_login_tokens.sql`, then:

- `requestLoginCode` / magic-link actions in `app/_actions/auth-email-actions.ts`
- `signIn('email-otp' | 'email-magic' | 'credentials')`
- Token cleanup: `/api/cron/cleanup-email-tokens` (Bearer `CRON_SECRET`, fail-closed)

`/register` redirects to `/login`. Do not import `EmailSignupForm` from the auth barrel.

Full env and CRM separation: [Ring Mailer](/docs/features/ring-mailer), [Email AI-CRM](/docs/features/email-ai-crm).

### Vitals + proxy soft-gate

| Module | Role |
|--------|------|
| `features/auth/lib/vitals-onboarding.ts` | `isVitalsGatedProvider` — google, google-one-tap, apple, email-otp/magic, telegram, crypto-wallet |
| `app/[locale]/login/onboarding/page.tsx` | Vitals form; clears `needsOnboarding` via session `update` |
| `proxy.ts` | Soft redirect when `getToken().needsOnboarding` on protected app routes |

### Google / Apple

- Google: `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` → `{origin}/api/auth/callback/google`
- Apple: `AUTH_APPLE_ID` / `AUTH_APPLE_SECRET` — see [Apple Sign-in Integration](/docs/examples/apple-signin-integration)

<Callout type="development" title="COOP">
  Primary Telegram **web** path is **redirect**. Login routes set `Cross-Origin-Opener-Policy: same-origin-allow-popups` so optional `telegram-login.js` popups are not blocked. Strict `same-origin` COOP breaks Telegram’s popup library. Mini App auth does not use popups — it posts `initData` to Credentials authorize. Profile linking uses the redirect Login Widget (no COOP change required on `/profile`).
</Callout>
