# Payments Overview

Ring Platform routes card and credit flows through **PaymentConductor** (`lib/payments/conductor/`). WayForPay is the primary PSP for Ukraine; Stripe is supported for international rails. Wallet credit top-up is a live `wallet_topup` purpose.

> **Deep dive:** [PaymentConductor feature](/docs/features/payment-conductor) · [Architecture](/docs/architecture/payment-conductor) · [WayForPay](/docs/features/wayforpay-integration) · [SubscriptionConductor](/docs/features/subscriptions)

## What PaymentConductor covers

| Purpose | Description | PSP / rail |
|---------|-------------|------------|
| `store_order` | Cart → checkout | WayForPay / Stripe / internal credit |
| `membership_upgrade` | Role upgrade (e.g. SUBSCRIBER → MEMBER) | WayForPay / Stripe / native token |
| `news_promotion` | News Kingdom sponsored articles | WayForPay / Stripe |
| `wallet_topup` | Fiat credit top-up (card / Apple Pay / Google Pay) | WayForPay |
| Internal credit | Spend existing credit balance | Internal |
| RING token | On-chain native-token payments | RING |

## What founders get

- **One ledger** — `payment_transactions` for store, membership, news, and wallet top-up.
- **Config-driven gateways** — `PAYMENT_DEFAULT_PROCESSOR` plus per-purpose overrides (`PAYMENT_STORE_PROCESSOR`, `PAYMENT_MEMBERSHIP_PROCESSOR`, `PAYMENT_NEWS_PROCESSOR`, `PAYMENT_WALLET_TOPUP_PROCESSOR`).
- **Admin visibility** — Payments tab on the user detail sheet lists membership and wallet top-up rows.
- **Membership UI** — PaymentModal: native-token and card are live; PayPal is a community FutureFeature (`membership-paypal`), not shipped.

    "supportedMethods": ["wayforpay", "credit_balance", "native_token"],

## Architecture

```
Checkout / upgrade / promotion / wallet top-up
        ↓
lib/payments/conductor/payment-conductor.ts
        ↓
Processors: wayforpay.processor | stripe.processor | internal-credit.processor
        ↓
payment_transactions (PostgreSQL, migration 004)
        ↓
lib/payments/conductor/webhook-dispatcher.ts → handlers/*
```

### Key modules

| Module | Path | Role |
|--------|------|------|
| Conductor | `lib/payments/conductor/payment-conductor.ts` | Routes by purpose + processor |
| Config | `lib/payments/payment.config.ts` | Config + env overrides |
| WayForPay | `lib/payments/processors/wayforpay.processor.ts` | HMAC, form/redirect, all four purposes |
| Stripe | `lib/payments/processors/stripe.processor.ts` | Checkout + webhook verify |
| Internal credit | `lib/payments/processors/internal-credit.processor.ts` | Credit deduction |
| Dispatcher | `lib/payments/conductor/webhook-dispatcher.ts` | Purpose routing |
| Webhooks | `app/api/payments/wayforpay/webhook`, `app/api/payments/stripe/webhook` | Canonical PSP callbacks |

### Environment variables

<Code language="bash" title="Payment + WayForPay SSOT">
{`PAYMENT_DEFAULT_PROCESSOR=wayforpay
WAYFORPAY_MERCHANT_ACCOUNT=your_merchant
WAYFORPAY_SECRET_KEY=your_secret
WAYFORPAY_MERCHANT_PASSWORD=your_password
WAYFORPAY_DOMAIN=ring-platform.org
WAYFORPAY_API_URL=https://api.wayforpay.com/api
STRIPE_SECRET_KEY=sk_live_...
STRIPE_WEBHOOK_SECRET=whsec_...
PAYMENT_FIAT_CURRENCY=USD
PAYMENT_STORE_PROCESSOR=stripe
PAYMENT_MEMBERSHIP_PROCESSOR=stripe
PAYMENT_NEWS_PROCESSOR=wayforpay
PAYMENT_WALLET_TOPUP_PROCESSOR=wayforpay`}
</Code>

No `WAYFORPAY_MERCHANT_ID`. Templates: `env.local.template`, `docker.env.template`, `docker-compose.template.yml`.
