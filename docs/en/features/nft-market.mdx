# NFT Exhibition Marketplace

<Callout type="success">
  The shipped marketplace is **Solana-first**: verified Ringdom **KEYS** gate NFTs list for **RING**. It replaces the older generic marketplace description with the live Exhibition flow.
</Callout>

The NFT Exhibition Marketplace lets members list, browse, buy, and cancel eligible Ringdom gate NFTs. A purchase transfers ownership, but **ownership alone does not unlock product access**. Buyers must stake the purchased gate through GateEscrow before `GateResolver.hasFeature` grants the related feature.

| Surface | Verified truth |
|---------|----------------|
| Marketplace | `/nft/market`, `/nft/market/[listingId]`, `/nft/market/sell` |
| Collections | `/nft/collections`, `/nft/collections/[slug]` |
| Search | Search redirects land on `/nft/market?q=...` |
| Feed | `useCursorFeed` with `moduleId="nft-market"` |
| Payment | RING only |
| Collection symbol | `KEYS` from gate collection metadata |
| Listing storage | `nft_listings` |
| Sale ledger | `nft_market_sales` |
| Collection cache | `nft_market_collections` |
| Migration | `data/migrations/031_nft_exhibition_market_schema.sql` |

## Why this matters for your clone

The marketplace turns tradeable vendor access keys into a visible economy. Operators can let a vendor sell a store deed, DAGI key, annual license, or quarterly license while keeping membership gates soulbound.

### Operator Checklist

- Enable NFT gates and marketplace config for the clone.
- Mint or import eligible vendor gates from the KEYS collection.
- Confirm sellers understand that staked gates must be unstaked before listing.
- Confirm buyers understand that a bought gate must be staked before benefits activate.
- Keep mainnet GateMarket disabled until the Anchor programs pass audit and Squads authority setup.

<Callout type="warning">
  Membership NFTs are soulbound and never listable. The marketplace is only for `vendor-store-deed`, `vendor-dagi-key`, `vendor-annual-store-license`, and `vendor-quarterly-store-license`.
</Callout>

### Listing Policy

<Steps>

<Step>
`isNftMarketplaceEnabled()` must pass. The config reads `nft.marketplaceEnabled` from `ring-config.json`.
</Step>

<Step>
The slug must be one of the four tradeable SKUs: `vendor-store-deed`, `vendor-dagi-key`, `vendor-annual-store-license`, or `vendor-quarterly-store-license`.
</Step>

<Step>
The template and ownership record must not be soulbound, the asset must verify against the KEYS collection, and there must be no active stake for the same asset.
</Step>

<Step>
An active listing blocks duplicate listings for the same asset. A staked gate blocks listing; an active listing means feature access is not active through staking.
</Step>

</Steps>

### Configuration Keys

| Key | Effect |
|-----|--------|
| `nft.marketplaceEnabled` | Enables listing policy for the marketplace |
| `nft.gateMarketProgramId` | Empty today means ledger-dev adapter; non-empty Anchor path throws in this build |
| `nft.marketplaceFeeRecipient` | Optional RING fee recipient |
| `nft.marketplaceFeeBps` | Fee split basis points, clamped from 0 to 10000 |

### Persistence

Migration `031_nft_exhibition_market_schema.sql` creates:

- `nft_listings` for active/draft/sold/cancelled listing rows and search text.
- `nft_market_sales` for idempotent purchase reservation and confirmation.
- `nft_market_collections` for collection aggregates and floor/listing cache.

<Callout type="development">
  `SolanaMarketClient.buyGate` currently settles through ledger-dev RING transfers when `gateMarketProgramId` is empty. The Anchor GateMarket CPI path is intentionally not implemented in this build.
</Callout>

The future program scaffold lives under `solana/programs/{gate-escrow,gate-market}`. `solana/SECURITY.md` blocks production or mainnet deployment until Smart Contract Security Auditor review, Squads authorities, pinned deployment records, and invariant tests are complete.
