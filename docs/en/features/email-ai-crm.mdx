# Email AI-CRM

<Callout type="info">
  Use **Founder** / **Developer** tabs in the docs sidebar to filter this page. Shared sections below apply to both audiences.
</Callout>

<Callout type="success" title="Executive summary">
Ring ships an **AI-assisted email CRM** for public contact mailboxes (for example `info@example.com`). Inbound mail is classified, threaded, and answered with Claude drafts; platform admins review, approve, and send from the admin UI under **`/admin/crm/*`**. Ingest is **IMAP cron poll** or an **inbound webhook**; persistence is PostgreSQL JSONB when migrations `009` + `010` are applied. HTTP APIs remain at **`/api/admin/email/*`**.
</Callout>

## Capability overview

| Layer | Responsibility |
|-------|----------------|
| **Ingestion** | `POST /api/cron/email-processor` (`action: poll`) or `POST /api/webhooks/email/inbound` |
| **Processor** | `services/email/email-processor.ts` — parse, security, AI, CRM, drafts |
| **Persistence** | `features/email-crm/lib/jsonb-collection.ts` → `db()` (`readDoc`, `upsertDoc`, `queryDocs`) on six JSONB collections |
| **Outbound** | `services/email/smtp/email-sender.ts` (nodemailer) — replies with `In-Reply-To` / `References` |
| **Admin UI** | `/admin/crm/inbox`, drafts, contacts, analytics, tasks, thread detail — plus `/admin/crm/orders` (project orders) |
| **Admin API** | `/api/admin/email/*` — `auth()` + `isPlatformAdmin` on every route (paths unchanged) |
| **Shell** | `CrmAdminShell` — horizontal tabs, `showRightRail={false}`, pageContexts `crm-*` |

## Why this matters for your clone

Public contact inboxes (`info@`, `support@`, `hello@`) are where trust is won or lost. Email AI-CRM gives operators a single admin surface to triage inbound mail, review AI drafts before send, and track follow-up tasks — without hiring a full support desk on day one. Project orders share the same CRM tab bar — see [Owner Project Lab](/docs/features/owner-project-lab).

### Business rules

- **Message-ID dedup** — the same RFC `Message-ID` is never processed twice (avoids duplicate LLM spend).
- **Auto-send off by default** — set `EMAIL_AUTO_SEND_ENABLED=true` only after an SMTP smoke test passes.
- **Cron poll in serverless** — production schedules `poll` every 1–5 minutes; `EMAIL_PROCESSOR_AUTOSTART` is for long-lived Node workers only.
- **Admin-only** — all `/api/admin/email/*` routes require a platform admin session.

### Admin pages (CRM shell)

| Route | Purpose |
|-------|---------|
| `/admin/crm/inbox` | Thread list (live API) |
| `/admin/crm/inbox/[id]` | Thread detail + messages |
| `/admin/crm/drafts` | Pending AI drafts — approve / reject / send |
| `/admin/crm/contacts` | CRM contacts registry |
| `/admin/crm/analytics` | Volume, intent/sentiment, API cost (from `email_api_usage`) |
| `/admin/crm/tasks` | Follow-ups and escalations |
| `/admin/crm/orders` | Project / custom orders desk (see Owner Project Lab) |

Navigation: **Admin → CRM** horizontal tabs (Orders \| Inbox \| Drafts \| Contacts \| Tasks \| Analytics). Right rail is hidden for CRM pages (`showRightRail={false}`).

<Callout type="warning" title="No redirects from /admin/email-*">
Legacy `/admin/email-*` page URLs are a **clean break** — update bookmarks and docs to `/admin/crm/*`. `ADMIN_EMAIL_*` route constants alias to the CRM paths. APIs and cron ids are unchanged.
</Callout>

### Operator setup

<Steps>

<Step>

Copy the **EMAIL CRM** block from `env.local.template` into `.env.local`. Set `IMAP_*`, `SMTP_*`, `ANTHROPIC_API_KEY`, and `CRON_SECRET`. Keep `EMAIL_AUTO_SEND_ENABLED=false` until verified.

</Step>

<Step>

Apply JSONB migrations on Postgres (`009_email_crm_jsonb.sql` + `010_email_crm_tasks_jsonb.sql`). For a quick UI-only test without tables, set `EMAIL_CRM_PERSISTENCE=memory` (data does not survive restarts).

</Step>

<Step>

Trigger ingest: schedule `POST /api/cron/email-processor` with `{"action":"poll"}` and `Authorization: Bearer $CRON_SECRET` every 1–5 minutes — or use the inbound webhook (see [developer guide](/docs/examples/email-ai-crm)).

</Step>

<Step>

Open **Admin → CRM Inbox** and **Drafts**. Approve a draft and send. Confirm the reply in the sender mailbox before enabling auto-send.

</Step>

</Steps>

## Processing pipeline

1. **Parse** — headers, body, attachments, thread keys (`References`, `In-Reply-To`).
2. **Security** — four-layer prompt-injection defense (`services/email/security/`).
3. **AI** — Haiku intent + sentiment; Sonnet response generation with prompt caching.
4. **CRM** — contact upsert, thread upsert, optional auto-tasks.
5. **Draft** — pending queue unless auto-send criteria are met.
6. **Notify** — `EmailNotificationService` (in-app / optional Slack) on draft, task, security block, urgent mail.

### Code layout

| Path | Role |
|------|------|
| `services/email/email-processor.ts` | Orchestrator; dedup, poll, ingest |
| `services/email/imap/` | Config, listener, `pollBatch()` |
| `services/email/smtp/email-sender.ts` | Outbound replies |
| `services/email/crm/` | Contact + task services |
| `services/email/drafts/` | Draft queue + auto-send rules |
| `services/email/ai/` | Classifiers, generator, cost tracker |
| `features/email-crm/lib/jsonb-collection.ts` | `readDoc` / `upsertDoc` / `queryDocs` → `db()` |
| `features/email-crm/repositories/` | JSONB repositories per collection |
| `features/email-crm/services/` | Thread, message, API usage services |
| `features/admin/crm/crm-admin-shell.tsx` | Shared CRM UI shell (`crm-*` pageContexts) |
| `app/api/cron/email-processor/route.ts` | Cron: `poll`, `status`, `mark-overdue-tasks` |
| `app/api/webhooks/email/inbound/route.ts` | HMAC-signed webhook ingest |

### Persistence — `jsonb-collection` → `db()`

All active CRM writes go through `features/email-crm/lib/jsonb-collection.ts`, which delegates to the platform `db()` singleton (`lib/database/DatabaseService.ts`):

| Helper | Delegates to |
|--------|----------------|
| `readDoc(collection, id)` | `db().readDoc()` |
| `upsertDoc(collection, id, record)` | `db().readDoc()` + `updateDoc()` or `createDoc()` |
| `queryDocs({ collection, filters, orderBy, limit })` | `db().queryDocs()` |
| `deleteDoc(collection, id)` | `db().deleteDoc()` |

Repositories (`jsonb-contact-repository.ts`, `jsonb-draft-repository.ts`, `jsonb-task-repository.ts`) and services (`email-message-service.ts`, `email-api-usage-service.ts`) import these helpers — they do **not** issue raw SQL.

### Active JSONB collections (migrations 009 + 010)

| Collection | Document id | Indexed fields |
|------------|-------------|----------------|
| `email_threads` | RFC thread root / Message-ID | `status`, `fromEmail`, `lastMessageAt` |
| `email_contacts` | `contact_<sha256(email)>` | `email`, `type` |
| `email_messages` | RFC Message-ID | `threadId` |
| `email_drafts` | `draft_<uuid>` | `threadId`, `status` |
| `email_tasks` | `task_<uuid>` | `threadId`, `status`, `dueDate` |
| `email_api_usage` | `req_<timestamp>_<random>` | `timestamp`, `operation`, `emailId` |

Factory: `getEmailContactService()` / `getEmailTaskService()` / `getEmailDraftService()` use Postgres unless `EMAIL_CRM_PERSISTENCE=memory`.

### Cron actions

`POST /api/cron/email-processor` accepts `action`: `poll` (default), `status`, `mark-overdue-tasks`, and optionally `start` / `stop` when `EMAIL_PROCESSOR_ALLOW_HTTP_START=true`.

</Audience>

## Schema-only tables (not wired in app)

<Callout type="development" title="Deprecated 001 column-model tables">
The legacy migration `001_email_crm_schema.sql` defines **`email_analytics`**, **`email_knowledge_base`**, and **`email_security_events`** as column-model tables. **No TypeScript module reads or writes these tables today.** Production uses JSONB migrations `009` + `010` only. Cost tracking persists to `email_api_usage`; RAG uses `InMemoryKnowledgeRepository` in `services/email/knowledge/knowledge-base.ts`.
</Callout>

<Callout type="development" title="Backlog — not yet production-persisted">
| Planned capability | Current state |
|--------------------|---------------|
| **PGVector knowledge base** (`email_knowledge_base`) | In-memory default docs via `getKnowledgeBaseService()` — no `jsonb-collection` table |
| **Security event audit trail** (`email_security_events`) | Security pipeline blocks in-flight; events are not persisted to Postgres |
| **Daily analytics rollup** (`email_analytics`) | Admin analytics aggregates from `email_api_usage` JSONB at query time — no daily rollup table |
</Callout>

## Local configuration

Add to **`.env.local`** (canonical comments in `env.local.template` **EMAIL CRM** block):

<Code language="env" title=".env.local — Email AI-CRM essentials">
{`IMAP_HOST=mail.example.com
IMAP_PORT=993
IMAP_TLS=true
IMAP_USER=info@example.com
IMAP_PASSWORD=

SMTP_HOST=mail.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=info@example.com
SMTP_PASSWORD=

ANTHROPIC_API_KEY=

CRON_SECRET=generate-a-long-random-string
EMAIL_AUTO_SEND_ENABLED=false
EMAIL_CRM_PERSISTENCE=memory
WEBHOOK_EMAIL_SECRET=`}
</Code>

| Variable | Purpose |
|----------|---------|
| `IMAP_*` / `SMTP_*` | Community inbox (any IMAP/SMTP provider) |
| `ANTHROPIC_API_KEY` | Intent, sentiment, and draft generation |
| `CRON_SECRET` | Bearer token for `/api/cron/email-processor` |
| `EMAIL_AUTO_SEND_ENABLED` | Keep `false` until SMTP smoke test passes |
| `WEBHOOK_EMAIL_SECRET` | HMAC for `POST /api/webhooks/email/inbound` (optional alternative to IMAP) |
| `EMAIL_CRM_PERSISTENCE` | `memory` for quick local UI tests; omit when using migrations `009`/`010` |
| `EMAIL_POLLING_INTERVAL` | Poll interval in ms (default `30000`) |
| `EMAIL_PROCESSOR_AUTOSTART` | Long-lived worker IDLE mode — not for serverless cron |

<Callout type="warning" title="Deprecated migration">
Do **not** apply `001_email_crm_schema.sql` (column-model CRM). Use **`009` + `010` JSONB migrations** only. See [developer guide](/docs/examples/email-ai-crm).
</Callout>

## Production deployment

On k8s or Vercel cron, store the same variables in your secret manager, apply migrations `009` + `010`, and schedule:

<Code language="bash" title="Production cron poll (every 1–5 min)">
{`curl -sS -X POST "$BASE_URL/api/cron/email-processor" \\
  -H "Authorization: Bearer ${CRON_SECRET}" \\
  -H "Content-Type: application/json" \\
  -d '{"action":"poll"}'`}
</Code>

Optional analytics snapshot: `GET $BASE_URL/api/cron/email-analytics` with the same Bearer token.
