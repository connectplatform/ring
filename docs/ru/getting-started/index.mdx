# Начало работы

Разверните **white-label клон Ring Platform** на своей машине. Этот хаб отражает реальный dev-flow из open-source дерева ([connectplatform/ring](https://github.com/connectplatform/ring)) и **ring-platform.org** — community-портала для self-hosted энтузиастов.

<Callout type="info" title="Реалистичный бюджет времени">
| Путь | Время | Результат |
|------|-------|-----------|
| **`./install.sh --quick`** + существующий PostgreSQL | ~20–40 мин | Клон, зависимости, env — схему и OAuth ещё нужно добавить |
| **Полный Postgres-primary bootstrap** | 45–90 мин | Локальный стек как в production (`k8s-postgres-fcm`) |
| **Прототип (`firebase-full`)** | ~15–30 мин | Только Firestore — без глубины ERP, News Kingdom, PaymentConductor |

Сначала видение? [Добро пожаловать в Ring](/docs/welcome), затем вернитесь сюда.
</Callout>

<Callout type="warning" title="OSS self-host vs Ringdom-managed">
**Self-host с GitHub?** Эта секция для вас. **Turn-key хостинг Ringdom?** Начните на [ringdom.org](https://ringdom.org) — после handoff см. [Руководство по кастомизации](/docs/customization/customization-guide). Публичное OSS-дерево содержит `install.sh`; enterprise k8s/CLI остаётся за публичной границей ([`FEATURESET.md`](https://github.com/connectplatform/ring/blob/main/FEATURESET.md)).
</Callout>

## Что вы настроите

| Слой | Артефакт | Назначение |
|------|----------|------------|
| **Идентичность клона** | `ring-config.json` | Брендинг, feature flags, домены (`ring-config.template.json`) |
| **Секреты и backend** | `.env.local` | `DB_BACKEND_MODE`, `AUTH_*`, Firebase FCM, tunnel deploy target |
| **Данные приложения** | PostgreSQL `ring_platform` | `data/schema.sql` v4.0.1+ + kingdom migrations |
| **Auth** | Auth.js v5 (`auth.ts`) | `AUTH_SECRET` + минимум один OAuth-провайдер |
| **Dev runtime** | `server.ts` | `npm run dev` — Next.js 16 + React 19 + native WSS при `RING_DEPLOY_TARGET=self-hosted` |

## Рекомендуемый bootstrap (Postgres-primary)

<Callout type="success" title="Типично для ring-platform.org">
Production и локальный dev используют **`DB_BACKEND_MODE=k8s-postgres-fcm`** — PostgreSQL для данных, Firebase Admin **только для FCM push**, если настроено.
</Callout>

<Steps>

<Step>

### 1 — Клон и `install.sh`

<Code language="bash" title="terminal">
{`git clone https://github.com/connectplatform/ring.git
cd ring
chmod +x install.sh
./install.sh --quick`}
</Code>

`install.sh` v2.0 (см. [`INSTALL.md`](https://github.com/connectplatform/ring/blob/main/INSTALL.md)):

- Проверка системных требований (Node.js 20+, npm 10+)
- Создаёт **`ring-config.json`** из шаблона (`--clone-name` для white-label slug)
- Копирует **`env.local.template`** → **`.env.local`** с `AUTH_SECRET` и `WALLET_ENCRYPTION_KEY`
- Запускает **`npm install`**
- При необходимости материализует `next.config.mjs`, `docker-compose.yml`, `Dockerfile`

Флаги: `--quick`, `--clone-name my-ring`, `--verbose`, `--help`.

</Step>

<Step>

### 2 — PostgreSQL

Запустите Postgres 16+ и БД **`ring_platform`** (пользователь **`ring_user`**). Варианты:

- **Docker** — dev-контейнер (см. [Установка](/docs/getting-started/installation#postgresql-setup))
- **Ringdom monorepo** — `docker compose -f docker-compose.dev.yml up -d postgres` или `./infrastructure/postgres/bootstrap-brew-dev.sh`
- **Существующий сервер** — создайте БД и укажите `DB_HOST` / `DB_*` в `.env.local`

</Step>

<Step>

### 3 — Схема и kingdom migrations

<Code language="bash" title="terminal">
{`export DATABASE_URL="postgresql://ring_user:ring_password_2024@localhost:5432/ring_platform"
psql "$DATABASE_URL" -f data/schema.sql
psql "$DATABASE_URL" -f data/migrations/002_news_content_schema.sql
psql "$DATABASE_URL" -f data/migrations/003_news_kingdom_upgrade.sql
psql "$DATABASE_URL" -f data/migrations/004_payment_transactions.sql`}
</Code>

Полный порядок и матрица клонов: [Миграции БД](/docs/getting-started/migrations). Хелпер: `./scripts/run-migration.sh` для контейнера `ring-postgres-dev`.

</Step>

<Step>

### 4 — Auth и локальные URL

Минимум в `.env.local`:

<Code language="bash" title=".env.local">
{`DB_BACKEND_MODE=k8s-postgres-fcm
AUTH_SECRET=          # openssl rand -base64 32
AUTH_GOOGLE_ID=
AUTH_GOOGLE_SECRET=
NEXT_PUBLIC_BASE_URL=http://localhost:3000
RING_DEPLOY_TARGET=self-hosted
NEXT_PUBLIC_RING_DEPLOY_TARGET=self-hosted`}
</Code>

Добавьте Google OAuth redirect: `http://localhost:3000/api/auth/callback/google`.

Интерактивный мастер: `npm run setup:env` или `./scripts/setup-dev.sh`.

</Step>

<Step>

### 5 — Dev-сервер и валидация

<Code language="bash" title="terminal">
{`npm run dev`}
</Code>

Ожидайте: `Ready on http://localhost:3000 [self-hosted]` и native WSS на `/api/tunnel/ws`.

Далее [Первый успех](/docs/getting-started/first-success) — homepage, `/login`, entities/opportunities без ошибок адаптера БД. Опционально: `npm run type-check`, `npm run portal:health`.

<Callout type="success" title="Bootstrap завершён">
Откройте [http://localhost:3000](http://localhost:3000). Брендинг в `ring-config.json`, далее [Следующие шаги](/docs/getting-started/next-steps).
</Callout>

</Step>

</Steps>

## Альтернативные пути

<Tabs items={['Ручная настройка', 'firebase-full прототип', 'Ringdom monorepo dev']}>

<Tab value="Ручная настройка">

Без инсталлятора — тот же результат, больше контроля:

<Code language="bash" title="terminal">
{`git clone https://github.com/connectplatform/ring.git
cd ring
npm install
cp env.local.template .env.local
cp ring-config.template.json ring-config.json
# edit ring-config.json + .env.local
# provision PostgreSQL + apply migrations (шаги 2–3 выше)
npm run dev`}
</Code>

Подробно: [Установка](/docs/getting-started/installation).

</Tab>

<Tab value="firebase-full прототип">

Быстрый Vercel-edge прототип — **не** production data plane ring-platform.org:

<Code language="bash" title=".env.local">
{`DB_BACKEND_MODE=firebase-full`}
</Code>

Firebase Admin + client keys из `env.local.template`. Без `data/schema.sql`. Пробелы: [Выбор БД](/docs/customization/database-selection).

</Tab>

<Tab value="Ringdom monorepo dev">

Когда `ring-platform.org` в checkout Ringdom:

<Code language="bash" title="ringdom repo root">
{`docker compose -f docker-compose.dev.yml up -d postgres
cd ring-platform.org
npm install
# .env.local already or: npm run setup:env
npm run dev`}
</Code>

Манифест multi-clone Postgres: `infrastructure/postgres/DEV-DATABASE-MANIFEST.json`.

</Tab>

</Tabs>

## Краткая справка — bootstrap

| Задача | Команда |
|--------|---------|
| One-command install | `git clone … && ./install.sh --quick` |
| Env wizard | `npm run setup:env` |
| Dev env script | `./scripts/setup-dev.sh` |
| Apply migration | `./scripts/run-migration.sh data/schema.sql` |
| Dev server | `npm run dev` |
| Type check | `npm run type-check` |
| Portal health | `npm run portal:health` |
| Repo install guide | [`INSTALL.md`](https://github.com/connectplatform/ring/blob/main/INSTALL.md) |

<Callout type="tip" title="install.sh vs setup-dev.sh">
**`install.sh`** — первый bootstrap клона (config + `npm install`). **`setup-dev.sh`** — после клона, hardening env. **`npm run setup:env`** — интерактивный проход по существующему `.env.local`.
</Callout>
