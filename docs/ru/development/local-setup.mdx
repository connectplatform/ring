# Настройка локальной разработки

Руководство по настройке Ring Platform для локальной разработки.

<Audience for="founder">

## Что вам понадобится

- Node.js 22, pnpm/npm и Git, установленные на вашем компьютере
- PostgreSQL 16 + PostGIS (через Homebrew, Docker или нативную установку)
- Редактор кода (рекомендуется VS Code)

## Обзор настройки

1. Клонируйте репозиторий
2. Установите зависимости
3. Настройте переменные окружения из `env.local.template`
4. Настройте PostgreSQL и выполните миграции
5. Запустите сервер разработки

</Audience>

<Audience for="developer">

## Предварительные требования

### Необходимое программное обеспечение

- **Node.js 22** — [Скачать с nodejs.org](https://nodejs.org/)
- **npm 10+** или **pnpm 9+** — Менеджер пакетов
- **Git** — Контроль версий
- **PostgreSQL 16** с расширением **PostGIS** — Смотрите раздел настройки базы данных
- **VS Code** — Рекомендуемое IDE

### Дополнительные инструменты

- **Docker** — Для контейнеризированного PostgreSQL (альтернатива установке через Homebrew)
- **Postman** или **Bruno** — Тестирование API

## Установка

### 1. Клонирование репозитория

<Code language="bash" title="terminal">
{`git clone https://github.com/connectplatform/ring.git
cd ring`}
</Code>

### 2. Установка зависимостей

</Code>
  </Tab>
  <Tab value="pnpm">
    <Code language="bash" title="terminal">
{`pnpm install`}
</Code>
  </Tab>

### 3. Конфигурация окружения

Скопируйте шаблон окружения:

<Code language="bash" title="terminal">
{`cp env.local.template .env.local`}
</Code>

<Callout type="warning">
Переменная `DB_BACKEND_MODE` является **обязательной** — платформа не запустится без неё. Для локальной разработки с PostgreSQL установите `k8s-postgres-fcm`.
</Callout>

Настройте ваш файл `.env.local` со следующими обязательными переменными:

<Code language="bash" title="terminal">
{`# Режим бэкенда базы данных (ОБЯЗАТЕЛЬНО)
DB_BACKEND_MODE=k8s-postgres-fcm

# Подключение PostgreSQL
DB_HOST=localhost
DB_PORT=5432
DB_NAME=ring_platform
DB_USER=ring_user
DB_PASSWORD=ring_password_2024
DATABASE_URL=postgresql://ring_user:ring_password_2024@localhost:5432/ring_platform

# Auth.js v5
AUTH_SECRET=generate-a-random-secret-here
AUTH_TRUST_HOST=true
AUTH_GOOGLE_ID=your_google_client_id
AUTH_GOOGLE_SECRET=your_google_client_secret

# Приложение
NEXT_PUBLIC_BASE_URL=http://localhost:3000
NODE_ENV=development`}
</Code>

<Callout type="tip">
Сгенерируйте `AUTH_SECRET` с помощью: `npx @better-auth/cli secret`
</Callout>

Полный список поддерживаемых переменных и их описания смотрите в [Конфигурация окружения](/docs/en/deployment/environment.mdx).

### 4. Настройка базы данных

#### Вариант A: Docker (рекомендуется для локальной разработки)

<Code language="bash" title="terminal">
{`# Запуск PostgreSQL 16 с PostGIS
docker run -d \\
  --name ring-postgres-dev \\
  -e POSTGRES_USER=ring_user \\
  -e POSTGRES_PASSWORD=ring_password_2024 \\
  -e POSTGRES_DB=ring_platform \\
  -p 5432:5432 \\
  postgis/postgis:16-3.4`}
</Code>

#### Вариант B: Homebrew (macOS)

<Code language="bash" title="terminal">
{`brew install postgresql@16 postgis
brew services start postgresql@16

# Создание пользователя базы данных и базы данных
createuser ring_user -P   # пароль: ring_password_2024
createdb ring_platform -O ring_user`}
</Code>

<Callout type="info">
Для локальной разработки с несколькими клонами используйте скрипт инициализации `infrastructure/postgres/bootstrap-brew-dev.sh`. Смотрите `infrastructure/postgres/MIGRATION-KINGDOM-MATRIX.md`.
</Callout>

#### Выполнение миграций

<Code language="bash" title="terminal">
{`npm run db:migrate`}
</Code>

<Callout type="tip">
Файлы миграций находятся в директории `data/`. Исполнитель миграций читает `DB_BACKEND_MODE` для выбора правильного адаптера. Для локального PostgreSQL (`k8s-postgres-fcm`) он применяет SQL-миграции из `data/schema.sql` и `data/migrations/`.
</Callout>

### 5. Запуск сервера разработки

<Code language="bash" title="terminal">
{`npm run dev`}
</Code>

Приложение будет доступно по адресам:

- **Фронтенд**: http://localhost:3000
- **API маршруты**: http://localhost:3000/api/*
- **Проверка состояния**: http://localhost:3000/api/health

## Распространённые проблемы

### Порт 3000 уже используется

<Code language="bash" title="terminal">
{`npm run dev -- -p 3001`}
</Code>

### Отказано в соединении с базой данных

1. Убедитесь, что PostgreSQL запущен: `pg_isready`
2. Проверьте значения `.env.local` для `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`
3. Убедитесь, что база данных `ring_platform` существует
4. Подтвердите, что `DB_BACKEND_MODE` установлен на `k8s-postgres-fcm`

### Ошибки OAuth Auth.js

1. Убедитесь, что `AUTH_GOOGLE_ID` и `AUTH_GOOGLE_SECRET` указаны в `.env.local`
2. Проверьте, что `http://localhost:3000` есть в разрешённых URI перенаправления консоли Google OAuth
3. Убедитесь, что `AUTH_SECRET` установлен и одинаков
4. Формат URL обратного вызова: `http://localhost:3000/api/auth/callback/google`

### Firebase FCM не работает (необязательно)

Firebase используется только для push-уведомлений (FCM) в режиме `k8s-postgres-fcm`. Приложение будет работать без настроенного Firebase, но push-уведомления не будут доставляться. Настройте переменные `AUTH_FIREBASE_*` и `NEXT_PUBLIC_FIREBASE_*` при необходимости.
